## Architecture decisions worth flagging

1. **DFS Rank vs Ahrefs DR scale mismatch.** Ahrefs DR is 0-100, DataForSEO `rank` is 0-1000. The Phase 5 refresh endpoint uses DFS (no AHREFS_API_KEY in `.env`). UI labels everywhere read "DFS Rank" with a small hint "DataForSEO, 0-1000" to avoid confusion. The `domain_rating` column in Supabase holds whatever scale the source provides; queries should NOT assume 0-100.

2. **Pipeline-trigger infrastructure built for the first time.** Phase 5 `/api/authority/refresh` is the canonical pattern: Vercel Python BaseHTTPRequestHandler + DFS/Ahrefs REST via urllib + Supabase writes via REST. Phase 3 `runRecluster` and Phase 4 `runRecomputeContentPlan` are unblocked but not yet wired.

3. **`urllib` for Supabase from Vercel Python**, NOT the `supabase` Python lib. Matches `web/api/wqa/export.py` pattern. The supabase lib would slow cold-starts. Helpers: `_sb_get`, `_sb_insert`, `_sb_upsert` in `web/api/authority/refresh.py`.

4. **User override preservation across refresh.** The DFS refresh upserts `referring_domain` but deliberately omits `quality` and `notes` from the upsert payload — Postgres `ON CONFLICT` leaves them untouched. Same pattern for Phase 4's planned recompute.

5. **`DATAFORSEO_LOGIN` + `DATAFORSEO_PASSWORD` added to Vercel production env during Chunk 5 deploy** — they were missing. Future Vercel Python endpoints needing DFS will work without extra setup.
